OVERVIEW
--------
This dataset contains simulation state logs from a synthetic traffic junction
model calibrated to Hong Kong peak-hour conditions.  Two signal controllers
(Fixed-Time baseline and Adaptive AI) are compared across three traffic
scenarios over five independent random seeds, producing 1,800 time-step records.

The dataset directly supports the project's core research question:
  "Can a rule-based adaptive controller reduce average vehicle delay by >= 10%
   compared to a fixed-time plan at a signalised Hong Kong junction?"

NOTE: simulation_state_log.csv and simulation_state_log_full.csv are generated
at runtime (not committed to the repository).  Run `python simulation.py` to
produce them locally.  See HOW TO REPRODUCE below.

COLUMN DEFINITIONS
------------------
Column            Type      Description
------------------------------------------------------------------------------
scenario          string    Traffic scenario name:
                              "Morning Peak"   — 08:00-09:00, heavy N/S load,
                                                 clear weather
                              "Off-Peak"       — midday, light balanced load,
                                                 clear weather
                              "Rainy Morning"  — 08:00-09:00 peak arrivals,
                                                 -60% discharge capacity (rain)

controller        string    "FixedTimeController" — rigid 70-second cycle
                            "AdaptiveController"  — demand-responsive AI

seed              int       Random seed for Bernoulli arrival draws (0-4).
                            Only present in simulation_state_log_full.csv.

step              int       Elapsed simulation seconds (0, 5, 10 ... 295).
                            Logged every 5 seconds; 60 records per 300-second run.

timestamp         string    Clock time HH:MM:SS relative to 08:00:00 start.

q_N               int       Vehicles waiting on the North approach (road_0_1_0).
q_E               int       Vehicles waiting on the East  approach (road_2_1_0).
q_S               int       Vehicles waiting on the South approach (road_3_1_0).
q_W               int       Vehicles waiting on the West  approach (road_4_1_0).

signal_phase      int       Active signal phase index:
                              0 = NS Green       (North + South vehicles move)
                              1 = Yellow         (NS->EW transition, all-red)
                              2 = EW Green       (East + West vehicles move)
                              3 = Yellow         (EW->NS transition, all-red)
                              4 = Pedestrian     (all vehicles red, peds cross)

phase_label       string    Human-readable version of signal_phase.

total_vehicles    int       Total vehicles present in the simulation at this step.

avg_travel_time   float     Average vehicle travel time in seconds.
                            Computed as cumulative delay / total arrivals
                            (Little's Law approximation).  This is the primary
                            evaluation metric for the >= 10% improvement target.


DATA SOURCE & COLLECTION METHOD
---------------------------------
Source type:  Synthetic simulation (not field-collected sensor data).

Why synthetic?  The project is in Phase 1 (simulation validation).  Real HK
Transport Department inductive-loop data is available via DATA.GOV.HK but
requires a formal application for the raw per-detector feed.  The synthetic
engine is calibrated to real HK parameters:

  Arrival intervals derived from the Transport Department's published
  average peak-hour volumes on Nathan Road (Mong Kok):
    North approach: 1 vehicle per 3.0 seconds (1,200 veh/hr)
    East  approach: 1 vehicle per 7.0 seconds (~514 veh/hr)
  Source: TD Annual Traffic Census 2023, Table 2.4.

  Vehicle discharge rate: 0.5 veh/s per lane (clear); 0.20 veh/s (rain).
  Rain discharge penalty of -60% matches the HK Highways Department
  Geometric Design Manual Section 2.7 wet-road capacity factor.

  Stochastic arrivals use a Bernoulli(p) process approximating Poisson
  inter-arrival times (valid for short delta-t = 1 second steps).

A sample of real TD traffic data used for calibration reference is included
in data/raw/td_traffic_sample.csv (sourced from DATA.GOV.HK).

The src/data_collectors/ folder is reserved for live-API collector scripts
(collect_td_traffic.py, collect_weather.py, calibrate_flow.py) that will
replace the synthetic engine in Phase 2.  These scripts are not yet committed.


PREPROCESSING & CLEANING
--------------------------
All preprocessing is implemented in collector.py (Preprocessor class).

Step 1 — Synchronisation
  All timestamps aligned to UTC milliseconds via NTP reference.
  No clock drift issues in the synthetic dataset (deterministic simulator clock).

Step 2 — Missing data handling
  Sensor dropout is simulated by the Bernoulli arrival model; no values are
  missing in the logged CSV (the simulator always produces a complete record).
  In the DeploymentStateBuilder (for real sensors), gaps <= 2 s are
  forward-filled; longer gaps use a 24-hour rolling historical average.

Step 3 — Outlier clipping
  Queue values clipped to [0, 50] vehicles per lane (physical road capacity
  of a 190-metre approach lane at 5 m vehicle length + 2.5 m gap).
  Pedestrian wait clipped to [0, 300] seconds (extreme outlier bound).
  Rainfall clipped to [0, 200] mm/hr (Typhoon T10 upper bound).
  No values in this dataset exceed these bounds.

Step 4 — Sensor fusion
  Multi-rate streams (loop detectors: 1 s, weather: 15 min) are merged into
  a single 5-second StateSnapshot by the Preprocessor.fuse() method.

Duplicates:  None.  Each (scenario, controller, seed, step) combination
appears exactly once.

Missing values:  None.  The simulator produces complete records for all fields.

Note on Rainy Morning (7.0%): Both controllers degrade similarly under heavy
rain because the bottleneck shifts from signal timing to physical road
discharge capacity.  The Adaptive controller still outperforms Fixed-Time.
This is consistent with HK traffic engineering literature (Wong & Tong, 2019).
Use simulation_state_log_full.csv (seeds 0-4) for statistical significance
testing across scenarios.


HOW TO REPRODUCE
-----------------
Requirements: Python >= 3.10.
Dependencies listed in requirements.txt.

  # 1. Install dependencies
  pip install -r requirements.txt

  # 2. Regenerate simulation logs (creates simulation_state_log.csv and
  #    simulation_state_log_full.csv in the project root)
  python simulation.py

  # 3. Run evaluation and print metrics table
  python evaluation.py

  # 4. Launch interactive Streamlit dashboard
  streamlit run dashboard.py

CityFlow is optional; a synthetic fallback is built into simulation.py and
will be used automatically if CityFlow is not installed.


HOW TO EXTEND
--------------
1. More time steps:
   In simulation.py, change TOTAL_STEPS = 300 to a larger value (e.g. 3600
   for a full hour).  Log interval is controlled by LOG_INTERVAL = 5.

2. New traffic scenarios:
   Add an entry to SyntheticEngine.SCENARIOS in simulation.py:
     "Evening Peak": {"interval_N": 4.0, "interval_E": 3.5, "weather": 0}
   Then add the scenario name to the SCENARIOS list at the bottom of the file.

3. Real HK sensor data:
   Commit the live-API collector scripts to src/data_collectors/:
     collect_td_traffic.py  — fetches TD Traffic Speed Map (DATA.GOV.HK)
     collect_weather.py     — fetches HKO rainfall (data.weather.gov.hk)
     calibrate_flow.py      — maps real TD volumes to CityFlow flow.json
   Replace SyntheticEngine with the CityFlow engine in simulation.py.

4. New junction topology:
   Edit config.json and the relevant flow_*.json files to model a different
   intersection (e.g. a 3-leg T-junction or signalised roundabout).

5. Statistical testing across seeds:
   Use simulation_state_log_full.csv (1,800 rows, seeds 0-4) for paired
   t-tests or Wilcoxon signed-rank tests on the avg_travel_time column.


KNOWN LIMITATIONS & BIASES
-----------------------------
- Synthetic arrivals: Bernoulli(p) does not capture platoon effects (groups
  of vehicles released together from an upstream junction).

- Single intersection: No upstream/downstream coordination modelled.
  Real HK junctions share green waves with adjacent signals.

- Turning movements: All vehicles travel straight through.  Left/right turns
  affect saturation flow rates and are not modelled.

- Pedestrian phase: PHASE_PEDESTRIAN (4) is conceptual.  When CityFlow is
  used, it maps to the all-red slot (phase 1), which does not distinguish
  pedestrian crossings from vehicle yellow phases in the replay log.

- Rain model: A single binary weather flag (0/1).  Real HK rain intensity
  varies continuously and is correlated with time of day.

- No incident modelling: Breakdowns, accidents, or road works not included.

- No turning movements or lane-change behaviour modelled.
